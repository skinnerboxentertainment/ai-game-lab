# Skill: gamedev-wisdom

Query 4,285 atomic knowledge units distilled and curated from the Code Monkey
Unity YouTube channel (~855 videos) — mechanics, architecture patterns, gotchas,
and design decisions, filtered down to what's actually portable to this lab's
stack. This is a **second opinion source**, not ground truth: it comes from one
channel's take on Unity gamedev, filtered by an LLM pipeline that is fallible.
Treat it the way you'd treat a well-read colleague's advice — worth checking,
not worth blindly following.

## When to use

At **Frame** (deciding how to structure a system) or **Attack** (about to write
gameplay logic) — before inventing a pattern from scratch, check whether this
corpus already has a tested answer for it, or a documented gotcha to avoid.
Also useful at **Expand** when scoping what a feature actually needs.

Not a replacement for `pixijs-lab-pack.md` (this lab's own render/asset/input
rules) or `state-authority-pack.md` (this lab's own state ownership rules) —
those are prescriptive for this codebase. This skill is *external* prior art:
patterns and gotchas from a much larger sample of game development than any one
project accumulates.

## Data

`catalog.json` — a static export from the `ytdistill` project
(`C:\Users\oscar\AI WORKBENCH\code monkey YouTube transcript distillation`),
regenerated by running `ytdistill export-skill "@CodeMonkeyUnity" --output
<this dir>/catalog.json` in that project after any curation change there. It is
**not** live-synced — re-export manually when the source corpus improves.

Every unit has:

- `id` — traceable back to the source DB.
- `type` — `technique | concept | gotcha | code_pattern | best_practice | design`.
- `engine` — `general` or `unity`. Nearly all units here that remain `unity`
  are `context`-only (see below) — a deterministic gate in the source pipeline
  keeps engine-locked implementation detail out of `core` entirely.
- `relevance` — `core` (directly usable for design/code, engine-agnostic) or
  `context` (useful background, an engine-specific technique whose idea still
  travels, or an idea that's real but not central). **`drop` is never in this
  catalog** — only core+context units are exported.
- `title`, `detail` — the actual insight.
- `tags` — free-text topic tags (not a fixed taxonomy).
- `video_id` — source video, for tracing back to origin if you want more context.

## Query tool

```bash
node skills/gamedev-wisdom/query.mjs <search terms> [flags]
```

### Search (free-text, ranked)

```bash
node skills/gamedev-wisdom/query.mjs state machine enemy AI
node skills/gamedev-wisdom/query.mjs camera follow smoothing
node skills/gamedev-wisdom/query.mjs inventory grid drag drop
node skills/gamedev-wisdom/query.mjs save load versioning
```

The query matches across title, detail, and tags (tags weighted highest).
Results are ranked by relevance score, not chronological.

### Filters

| Flag | Effect |
|------|--------|
| `--type <type>` | `technique\|concept\|gotcha\|code_pattern\|best_practice\|design` |
| `--relevance <rel>`, `-r` | `core\|context` (default: both) |
| `--tag <tag>` | Exact tag match |
| `--video <video_id>` | All units distilled from one source video |
| `--top <n>`, `-n` | Limit results |
| `--json` | Output as JSON (default: Markdown) |

### Examples

```bash
# Core-only pathfinding patterns
node skills/gamedev-wisdom/query.mjs --relevance core pathfinding --top 5

# Every gotcha tagged 'camera'
node skills/gamedev-wisdom/query.mjs --type gotcha --tag camera

# Everything distilled from one specific video
node skills/gamedev-wisdom/query.mjs --video SD05YaY_XXY
```

## Integration with game building

1. **Translate the design question into query terms** — "how should enemy AI
   decide what to do" → `node query.mjs state machine enemy AI decision`.
2. **Run the query**, prefer `--relevance core` first; check `context` results
   too if core comes up thin — a `context` unit can still carry a real idea,
   it's just less directly actionable or engine-tied.
3. **Cross-check against this lab's own rules** — a pattern from the corpus
   that conflicts with `AGENTS.md`'s live rules (pure state core, fixed
   timestep, server authority, etc.) loses; those rules are non-negotiable
   here, the corpus is not.
4. **Cite it lightly in the spec/PR**, e.g. "flow-field pathfinding pattern,
   per gamedev-wisdom corpus" — not as an authority, just as a note on where
   an idea came from.

## Watch-outs

- **This is Unity-channel content filtered by an LLM curation pipeline**, not
  hand-vetted engineering doctrine. A `curative validation round` (manual spot
  audit) has been run once on the source corpus and corrected known issues
  (mislabeled C#-language trivia, a couple of false negatives in the dropped
  set) — see `validation_report.md` in the source project for the full
  methodology — but it was a sample-based audit, not exhaustive. Treat any
  single unit with the skepticism you'd give an uncredited blog post.
- A handful of `context`-relevance units are still `engine=unity` — read them
  for the underlying idea, not as copy-pasteable technique; they were kept
  specifically because the *idea* was judged to survive translation even
  though the *implementation* as described won't.
- Two near-identical units from different source videos are not a bug — the
  corpus keeps one atomic unit per video, so a popular technique (e.g. a
  flying death-effect prefab) can legitimately appear more than once with
  slightly different framing.
